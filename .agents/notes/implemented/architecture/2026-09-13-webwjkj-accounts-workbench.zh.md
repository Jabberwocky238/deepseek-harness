# Agent Note: webwjkj 账号与工作台

Status: implemented

[English](2026-09-13-webwjkj-accounts-workbench.md) | 中文

## 问题

独立 webwjkj 应用需要验证后的手机身份、可选邮箱和微信绑定，以及可扩展工作台，其中中央上下区域能够显示相同类型的面板。

好友申请使用版本 3 的账号 SQLite 数据库，以无向用户对建立唯一索引。精确匹配已验证身份的搜索仅返回 UUID、显示名和头像。只有已认证的收件人能处理申请，接受记录在读取目录时幂等投影为 IM 联系人。

## 决策

[webwjkj](../../../../packages/bundle/webwjkj/README.zh.md) 使用专用 SQLite 账号数据库，通过 Better Auth 管理会话和验证，通过腾讯云 SDK 发送短信、SMTP 验证邮箱、开放平台网站 OAuth 绑定微信。用户 ID 为 UUID。认证表单仅开放所需操作；跨进程文件锁串行执行验证码验证，唯一索引保证每个用户最多绑定一个微信且每个微信只有一个归属用户。生产环境地址要求 HTTPS。账号页面使用 same-origin 引用来源策略，让浏览器表单提交保留 Origin 头以进行 CSRF 校验。

四种并列登录方式分别使用已验证手机或邮箱的验证码、账号密码凭据以及微信 OAuth。登录页使用独立的全视口布局，表单居中，亮暗配色跟随系统，短信和账号密码使用标签切换，邮箱和微信使用图标切换；不加载首页样式或已认证工作台。新的已验证身份创建 UUID 用户，显式绑定则复用已有 UUID。账号登录使用 Better Auth 的 username 插件与密码哈希，不开放公开的密码注册端点。数据库版本 2 通过从版本 1 开始的事务迁移增加可空且唯一的登录账号字段。微信资料接口不提供邮箱，微信注册因此使用未验证的内部占位邮箱，该地址不会显示为已绑定邮箱。

应用直接编译从 code-server 的 VS Code 版本克隆并维护的 UI 源码。仓库只保留 Grid、Sash、ActionBar、Dialog 与 Codicon 的传递源码闭包。构建拒绝工作台、编辑器、平台、服务端、扩展宿主和外部运行时导入。UI 资源严格校验文件名与摘要，不支持的工作台与扩展 URL 返回 404。构建不应用源码补丁，也不安装预编译工作台。

左侧活动栏底部是设置，其上为个人资料。个人资料打开由应用管理的原生弹窗，退出直接返回登录页。账号安全使用工作区标签和工作台主题变量，复用已认证的服务端表单与验证文案，在标签内显示提交结果，仅微信授权使用整页导航。直接账号链接重定向到此标签。右侧和下方工作区打开时为空白。联系人列表使用已认证的 `webwjkj:<user UUID>` 身份，包含 default agent，支持接受后的好友关系以及仅由联系人创建的群聊。文字记录与发送消息限定在当前用户加入的会话中。

响应式导航将已有侧边栏与当前编辑器移入触屏布局，回到桌面时恢复原位置。二进制上传复用共享附件提供方，持久化消息持有附件引用，每次下载都检查会话成员身份。有界 multipart 读取器使用 IM 字节限制。消息编辑器保留重试使用的提交标识和已选文件。

webwjkj 管理标签、标签拖拽、会话面板、好友申请、通知和个人资料操作，VS Code 仅提供 UI 组件。亮色、暗色和系统主题共用同一套对话框，手动主题选择按 UUID 保存。默认 agent 通过隔离且无工具的模型内核处理已授权的私聊消息。每次回复将该会话的有限历史窗口记录到新的 Session，并把完整回复持久化到 IM，其他用户的聊天不会进入输入。消费方按会话串行处理请求，以确定性回复 ID 支持重试，在超时或关闭时中止并等待轮次结束。模型使用共享设置与凭据选择提供方，群聊自动回复保持关闭。

## 考虑过的替代方案

**移除图标的完整 VS Code 工作台。** 传递依赖可能重新注册 Chat 与开发工具的命令和视图。因此应用不包含完整运行时，仅构建 UI 依赖。

**自行实现认证和分隔条。** Better Auth 管理会话与验证，克隆的 Grid 和 Sash 管理尺寸调整，webwjkj 管理账号与消息操作。

可选本地测试配置在独立 `local-test` 子目录中，通过正常的密码哈希存储创建 `admin / 123123`。它要求显式配置和本机 HTTP 组合，并拒绝生产模式。普通启动不会创建测试账号或读取测试目录，服务商故障也不能启用默认凭据。测试账号已有密码在重启后保持不变。

## 影响

部署需要服务商密钥和已审核的腾讯云与微信应用配置。测试使用真实 Loader、HTTP 服务、Better Auth 和 SQLite，仅替换外部投递与 OAuth 调用；包内 HTML 快照覆盖账号和工作台输出。真实服务投递需要单独的有效凭据验证。独立首页决策继续有效；本决策添加认证功能，不改变官方 Web 应用。
