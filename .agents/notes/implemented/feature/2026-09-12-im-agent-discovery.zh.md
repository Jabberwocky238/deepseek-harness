# Agent Note: Agent 绑定的 IM 查询

Status: implemented

[English](2026-09-12-im-agent-discovery.md) | 中文

## Problem

AI 需要知道自身身份、联系人地址以及已加入的会话，以选择收件人，同时不能访问其他参与者的私有关系。

## Decision

IM 绑定为每个 AI 身份的唯一 Agent 注册 `im_context` 和 `talk`。联系人关系就是双向私聊授权，只存储一份；群成员关系独立允许群内消息。授权接口编辑联系人，而非另一层权限。

每个 AI 持久化当前群或联系人页面，也可以不打开任何页面。只有当前页面的正文会在下一次尚未启动的工具前排队进入。其他会话发送合并后的发送者计数提醒，并保留未读正文。提醒可以忽略；打开页面后才将未读消息排入队列。普通 assistant 文本保持私有，只有 `talk` 发布消息。身份来自绑定，不接受模型指定列表所有者。

[Agent 作用域决策](../architecture/2026-07-08-agent-scope-contexts.zh.md)继续负责注册可见性和生命周期。[WeCom 会话决策](2026-09-12-wecom-owned-conversations.zh.md)负责独立的外部传输会话。这两个决策均未被取代。

IM 提供持久化消息与 Agent 工具，不提供独立聊天面板。外部适配器负责用户交互；共享服务不需要另设浏览器联系人与会话编辑器。

## Alternatives considered

接受任意参与者 ID 的全局工具允许以错误身份查询私有关系。将联系人复制进系统提示词会让关系变更失效，并在不需要查询时也占用上下文。

## Consequences

查询通过持久化工具结果和通用工具展示返回最新数据。测试覆盖两个独立身份、排除私有会话、实时移除联系人、未绑定 Agent、双向联系人撤销、无需联系人即可群内交流、页面选择与离开以及模型可见日志。包内预期输出文件固定返回文本；正式 profile 的 Session 回放仍是覆盖缺口。
