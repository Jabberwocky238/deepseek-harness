# Agent Note: WeCom owned conversations

Status: implemented

[English](2026-09-12-wecom-owned-conversations.md) | 中文

## 问题

企微用户需要多轮 Agent 对话，并在原传输通道接收回复。Webhook 运行时创建独立 Session，但不跟踪完成状态，因此无法管理这一对话生命周期。

## 决策

[企微插件](../../../../packages/interaction/wecom/README.zh.md)使用持续维护的企微 SDK 实现长连接传输。插件管理有界的会话队列及 Agent 句柄映射。单聊归属一个用户；群聊会话归属群与用户组合。显式白名单在创建任何 Agent 前控制消息接纳；`*` 接纳该机器人的所有发送者，空列表拒绝所有用户。通配符仍保留机器人身份校验和按用户分隔的历史。

每个队列拥有从空闲到再次空闲的活动区间。一个企微流以处理状态开始，通过 `agent/assistant-stream` 接收合并后的文本预览；最终更新使用最后一条已提交的助手文本。失败尝试清除暂定预览，错误或超时通过状态结束流。推理及工具调用片段不对外发送。每条消息仅保留最新未发送预览及一个待确认更新。不声称该输出仅由某条后续消息导致。[活动区间决策](../architecture/2026-07-30-followup-enqueue-and-owned-runs.zh.md)继续作为依据。[Webhook 决策](2026-08-22-fire-and-forget-webhook-sessions.zh.md)管理独立的投递触发 Session，保持不变。这两份记录均未被取代。

原生 HTTP 下载在 SDK 解密前落实字节预算和取消，避免 SDK 下载辅助方法的无界缓冲及缺少取消参数。附件服务验证图片批次并原样保存文件；日志消息仅保留持久引用，不包含临时 URL 或解密密钥。现有模型请求投影负责图片传递及文件句柄文本。

消息标识在处理结束前保留为待处理状态，随后进入有界的已完成标识集合。回复失败不会重新执行任务。Session 持久化负责 Agent 日志，会话对应关系及去重状态仅保存在进程内。插件卸载时停止接纳、断开传输、释放其拥有的 Agent，并等待队列结束。

可选 IM 工具沿用机器人与用户、或机器人与群及用户组合的所有权。独立的持久命名空间防止 Agent 查询其他用户的联系人或会话。显式且相同的 `imBotContacts` 名单仅让列出的机器人在同一用户和聊天下共享命名空间。固定的机器人身份保留各自的真人会话；互相添加联系人并创建共享 AI 私聊，使机器人能够显式互发消息，而不暴露无关用户。每个企微回调在模型输入前选择已认证的真人或群聊页面。IM 服务负责发送记录和投递状态；SDK 将已接纳的 `talk` 文本和媒体发送到已认证回调的目标。Agent effect 管理工具与出站接收器。普通流式回复不进入 IM 发件箱。每个会话的发送预算在重载后保留；修改已有预算需要更新已保存的会话。

## 考虑过的替代方案

**复用 Webhook 运行时。** 其发送后不跟踪的语义不提供多轮所有权或完成回复。为聊天扩展它会改变无关的公开职责。

**在群内共享一个 Agent。** 这会让成员读取其他成员的对话上下文。按成员分隔历史可提供明确隔离，同时保留部署的共享工作目录。

**立即持久化映射及发件箱。** 持久回放与投递需要独立的事务及重试保证。普通回复明确说明重启与投递限制；可选 IM 发送使用现有 IM 存储。

## 影响

传输重连不会丢弃运行中的对话历史。重载会开启新对话，旧消息标识在淘汰或重启后可能再次被接纳。多个插件条目分别管理机器人连接、会话对应关系和消息标识集合。完成回复使用已提交文本；本地测试使用回环连接上的真实 SDK 和真实 Agent 循环。验证部署认证及投递仍需要真实凭据。
