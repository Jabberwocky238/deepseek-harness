# Agent Note: 多个数据湖与目录内地图

Status: implemented

[English](2026-09-13-data-lake.md) | 中文

## 问题

Agent 需要导航多个磁盘或 S3 数据集，定位每个文件所属目录的地图，并在每个层级保存变化摘要。现有存储中心管理结构化应用记录，不管理与外部数据根目录同位置的清单。

## 决策

[数据湖服务](../../../../packages/storage/data-lake/README.zh.md) 管理多个具名数据湖。每个湖恰好拥有一个根索引，以及任意数量的嵌套目录地图。地图仅包含直接子项，与 Agent 编写的摘要一起保存在各目录的保留元数据文件夹内。源提供者实现清单和元数据 IO；索引器使用该接口，在地图写入后发布根索引。

目录版本包含子级版本，因此后代变化会使祖先摘要过期。Agent 针对已索引版本提供文字摘要；索引器拒绝旧版本写入，且不生成替代摘要。面向模型的消费者通过写入日志的工具结果暴露选定记录，不添加隐藏模型上下文。

## 考虑过的替代方案

**每个服务只配置一个根路径。** 同一服务必须向同一 Agent 暴露多个独立数据湖，因此根路径属于具名湖配置。

**外部元数据存储。** 需求规定地图和摘要保存在对应源目录内，包括 S3 前缀。因此这些记录不由存储中心管理。

**程序生成摘要。** 文件统计不能替代所需的 Agent 变化解读。扫描只识别变化并使摘要过期。

## 影响

每个湖拥有独立的串行修改队列，并独立选择磁盘或 S3 提供者。就地存储要求源根路径的元数据写入权限。完整扫描在内存中保留索引，配置限制可接收条目数。旧元数据保留，不协调多进程，仅包含元数据的 S3 前缀仍可导航。磁盘变化检测使用大小和修改时间，不读取每个文件的内容。

磁盘专项测试覆盖层级、实际地图位置、摘要过期、旧版本写入、扫描失败、符号链接与湖隔离。Loader 测试覆盖配置激活；HTTP S3 夹具覆盖 SDK 分页、就地写入和摘要读取。实际 S3 验证需要部署凭证。
